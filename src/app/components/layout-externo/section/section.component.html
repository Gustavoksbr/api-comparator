Compare as diferenças de requisições entre alguns estilos arquiteturais baseados no protocolo HTTP (REST, GRAPHQL e SOAP) em um sistema de cursos

REST

Fornece uma forma simples e padronizada de gerenciar recursos pela web. Uma boa opção para CRUD

  • Utiliza o protocolo HTTP.
  • Métodos principais: GET, POST, PUT e DELETE (entre outros).
  • URLs são dinâmicas (podem conter path params ou query params).
  • Geralmente utiliza o formato JSON, mas pode ser configurado para XML também
  • Status codes comuns: 200, 201, 204, 400, 401, 403, 404, 409, 500...

GraphQL

Permite que o cliente defina exatamente quais dados deseja receber, reduzindo o número de requisições e evitando sobrecarga de dados. Uma boa opção para consultar dados complexos

  • Utiliza o protocolo HTTP.
  • Método: apenas POST.
  • URL é fixa; o que varia é o corpo da requisição (body).
  • Possui sua própria linguagem de consulta
  • Status code: normalmente 200. Em caso de erro, o retorno contém um objeto com o campo "errors": [...].
  • Permite ao cliente escolher exatamente quais atributos deseja receber na resposta.

SOAP

Possui um padrão rigoroso de mensagens e é geralmente utilizado em integrações entre sistemas de back-end. Atualmente é considerado obsoleto, sendo recomendado apenas em sistemas legados ou para integração com eles.

  • Geralmente utiliza HTTP, mas pode usar outros protocolos de comunicação, como SMTP ou JMS (Java Message Service).
  • Método: apenas POST.
  • URL é fixa; o que muda é o corpo da requisição (body).
  • Utiliza o formato XML
  • Status codes comuns: 200 (sucesso) e 500 (qualquer tipo de erro).
